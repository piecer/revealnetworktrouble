# Android IP context v1

Android adds an explicit, optional metadata lookup beside the existing report and Geo disclosure. It does not rerun diagnostics or request capabilities. The immutable `Report`, its original received JSON, and `ReportMarkdownExporter` remain unchanged. Context is memory-only and is not included in either existing export.

## Interaction and provenance

Open **Show IP context** / **IP 추가 정보 펼치기**, select the full IP with the reusable previous/next controls, then press **Look up IP context** / **IP 추가 정보 조회**. Opening, rendering, selection and paging send no request. One lazily mounted panel displays one IP; collapsing removes its children and cancels delivery authority. The selector has one address slot, not a widget per address. It is independent of diagnostic busy/ready state and report sharing.

The warning explains that the selected IP goes through the configured API to the system resolver, an RDAP registry and RIPE RIS/RPKI. The panel shows source, app acquisition time, server expiry, explicit API versus app-memory-cache provenance, each component status, omissions, names and forward confirmation, network range/organization/type/country/events, prefix/origin ASNs and RPKI validity.

Section-local caveats distinguish naming consistency from identity/trust/location, registration from the physical operator/location, the external RIS 8-hour dump from instantaneous announcements or the measured traceroute, and RPKI origin authorization from network health or an attack verdict. No provider contacts, links, automatic navigation, aliases or map redesign are added. IP identity and existing aliases remain unchanged. Country means registration country. An RPKI `unknown` result means no applicable ROA, not failed acquisition.

English remains the default resource language. Korean resources cover all new strings and the existing Activity controls: introducing a Korean resource configuration without those supporting translations makes the existing canonical missing-translation lint gate fail. Existing default strings and the human-export implementation are unchanged.

## Boundaries

* `IPContextAddresses` projects only validated compact `opaqueData()` nodes or eligible full-report attempts/representative topology. It retains canonical public, responsive positive-hop observations, including those without Geo, coordinates or RTT. Failed/error-bearing/status-inconsistent attempts, unknown/local/synthetic-failure nodes and private/reserved/noncanonical addresses are excluded. The existing report parser bounds source topology nodes to 8192 and containers to 32768. Deduplication preserves first-observation order; output is at most 500 unique IPs with exact omitted accounting. There is no invented node-list API.
* `IPContextJson` consumes original UTF-8 bytes, capped inclusively at 16384, with depth/token admission before recursive materialization. It rejects malformed UTF-8, duplicate decoded keys, bad escapes, unpaired surrogates, null, booleans and extra documents. It uses neither `org.json` nor floating point. Integer normalization is exact: `1e0` is one; a tiny nonzero fraction cannot round to an integer; zero with arbitrarily large exponents remains exactly zero.
* `IPContextParser` closes every object and status/field matrix, validates UTC Gregorian millisecond timestamps, stable/transient TTL, component/RPKI chronology, request-address equality, canonical range/prefix containment, masked host bits, sorted unique names/origins, UTF-8 field/count limits and canonical Go-encoding size. `IPContext` exposes only immutable nested maps/lists and safe typed identity/time accessors, independently of reports.
* `ApiConnectionConfig.contextEndpoint()` resolves only `/api/v1/ip-context` on the existing validated API origin. Existing HTTPS/debug-loopback and Bearer policy is reused. Credential-reflecting decoded metadata is rejected as a whole without rewriting the schema or exposing reflected text. Error bodies are not read or displayed.
* `IPContextTransport` performs one POST containing only `address`, with no query string, redirect following or application retry. It uses one captured 10-second total monotonic operation budget, bounded socket timeouts, a cancellation/deadline disconnect, and strict 16384-byte streamed admission. HTTP 404 is a local unsupported result; it never triggers checks or reports. Non-success HTTP responses use fixed context-specific labels, not raw server prose.
* `IPContextSession` is a separate retained owner. It has one physical work lease, no replacement admission/queued work while a cancelled callback remains active, generation-fenced completion, attachment-fenced listener delivery and final-publication deadline checks. Retained dispatch messages capture neither an Activity nor its listener. Detach drops the listener; recreation retains the independent session and selected IP, with disclosure initially collapsed. Final destruction revokes work and shuts down the owned executor.
* Report/config replacement clears the cache and revokes old success/error/finally authority. Selection/collapse cancels and changes delivery generation. Cache is a deterministic access-order LRU of at most 64 entries, scoped to the exact report and API config (including ephemeral auth authority), respecting server expiry. Only explicit requests initiate acquisition; cache display is locally labelled. Context failures never invalidate the ready report, Geo details or ordinary sharing.

## Verification and acceptance scope

Permanent tests run in both debug and release via unchanged `make android-test`, including the same unchanged `testdata/ip-context-corpus.json`: SHA-256 `5976737708e238833b2491f707c7f2365ca73193397407b7b5cda89b6f3a3843`, 192 case identities, 60 accepted / 132 rejected, 46 producer snapshots. Each case decodes the exact `wire_base64` bytes and compares the producer-derived projection oracle; this is not an independent semantic oracle. XML stdout records case identity, input-byte hash, provenance and projection equality.

The regressions include actual MainActivity render/actions and sharing Intents, real attach/detach/configuration recreation, delayed success/error/finally and final-publication expiry, auth/base/report invalidation, private/foreign selection, cache bounds/expiry, all context-failure classes, partial component labels, no-Geo/full projections, 500-address paging with exact omissions, Korean action labels and bounded native layout at several widths. A real loopback HTTP peer exercises production context POST delivery of accepted corpus bytes; it is explicitly a transport fixture, not the Go API. The parent has a separate real-Go-API fixture and `API-BRIDGE-HANDOFF.md` lists the actual Activity/transport/session seams for that additional acceptance.

Canonical gates are separate: `make android-test`, `make android-lint`, `make android-assemble`. Source-bound receipts and exact raw XML live outside the product snapshot in the Android implementation evidence directory. Physical devices, TalkBack/Switch Access, OEM scrolling/glyph rendering, release signing, deployment, port 3000, public-provider availability and cross-root APK reproducibility are not claimed. Release assembly produces the project's unsigned release APK; no signing or platform/dependency changes are introduced.
